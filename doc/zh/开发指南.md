# OpenAN Observability SDK for Java：开发指南

[English](../en/development-guide.md) · [API 参考](API参考.md)

本文档说明如何在 Java 应用中接入 SDK、配置 Collector、编写三类观测信号，以及维护随 SDK 打包的信号定义。

## 1. 前置条件与依赖

- JDK 17 或以上；
- Maven；
- 可访问的 OpenTelemetry Collector；
- 发布版本可从 Maven Central 引入。开发 SDK 本身时，可先在仓库根目录执行 `mvn -B -ntp install`，使本地 Maven 仓库可用。

应用的 Maven 依赖：

```xml
<dependency>
  <groupId>net.openan</groupId>
  <artifactId>observability-sdk</artifactId>
  <version>0.1.0-SNAPSHOT</version>
</dependency>
```

## 2. 初始化与生命周期

一个进程通常创建一个 `ObservabilitySdk`。配置值优先于环境变量。服务停止、命令行进程退出或测试结束前，执行 `flush` 并关闭 SDK。

```java
try (var sdk = ObservabilitySdk.start(SdkConfig.builder()
        .serviceName("diagnosis-agent")
        .endpoint("http://localhost:4317")
        .protocol("grpc")
        .build())) {
    var observe = sdk.observe();
    // 采集业务信号
    if (!sdk.flush(10, TimeUnit.SECONDS)) {
        throw new IllegalStateException("OTLP export failed or timed out");
    }
}
```

`flush` 的 `false` 返回值表示等待超时或自上次调用以来检测到导出失败。请将其纳入应用退出、批任务和集成测试的失败处理。

运行时可调用 `sdk.setEnabled(false)` 停止创建新的信号，调用 `sdk.setEnabled(true)` 恢复。开关前创建的 Span 仍可结束并导出。

## 3. 接入三类观测信号

### 3.1 A2A / A2A-T

对 A2A 请求创建 Client 或 Server Span。A2A-T 消息和日志需带 `extension.name`，该值决定其余可用属性：

| `extension.name` | 属性示例 |
|---|---|
| `task-t` | `task.type`、`task.object` |
| `negotiation-t` | `negotiation.id`、`negotiation.round`、`negotiation.result`、`negotiation.performative` |
| `notification-t` | `notification.topic`、`push.notification.url` |
| `authorization-t` | `authorization.stage`、`authorization.policy.operation.type` |

Task-T 的 Span、Log 以及 `task.duration`、`task.count` 指标都要求非空 `task.type`。

```java
var task = Map.of("extension.name", "task-t", "task.type", "diagnosis");
try (var span = observe.trace("SendMessage", SignalKind.CLIENT, task)) {
    observe.log("gen_ai.agent.a2at.message", LogSeverity.INFO,
        "diagnosis completed", task, span);
    observe.metric("task.duration", 42_000, Map.of("task.type", "diagnosis"));
    observe.metric("task.count", 1, Map.of("task.type", "diagnosis"));
    span.ok();
}
```

### 3.2 Workflow

Workflow Trace 名称固定为 `a2at.workflow`，要求 `workflow.id`、`workflow.type`、`workflow.status`。步骤 Trace 使用 `a2at.step.<step-name>`，要求步骤名称、序号和状态。

```java
var workflow = Map.of(
    "workflow.id", "wf-001",
    "workflow.type", "fault-diagnosis",
    "workflow.status", "running");
try (var workflowSpan = observe.trace("a2at.workflow", SignalKind.INTERNAL, workflow);
     var workflowScope = workflowSpan.makeCurrent()) {
    var step = Map.of(
        "workflow.step", "retrieve-alarms",
        "workflow.step.index", 1,
        "workflow.step.status", "completed");
    try (var stepSpan = observe.trace("a2at.step.retrieve-alarms", SignalKind.INTERNAL, step)) {
        observe.metric("step.duration", 75, Map.of(
            "workflow.step", "retrieve-alarms",
            "gen_ai.agent.name", "diagnosis-agent"));
        stepSpan.ok();
    }
    observe.metric("workflow.duration", 180, Map.of(
        "workflow.type", "fault-diagnosis", "workflow.status", "completed"));
    workflowSpan.ok();
}
```

`workflow.duration`、`workflow.count` 要求 `workflow.type` 与 `workflow.status`；`step.duration` 要求 `workflow.step` 与 `gen_ai.agent.name`。

### 3.3 Agent

Agent 子步骤 Trace 使用 `a2at.substep.<substep-name>`，需要 Agent 名称、子步骤名称和状态。`agent.skills` 是字符串列表。

```java
var substep = Map.of(
    "gen_ai.agent.name", "diagnosis-agent",
    "substep.name", "retrieve-alarms",
    "substep.status", "completed");
try (var span = observe.trace("a2at.substep.retrieve-alarms", SignalKind.INTERNAL, substep)) {
    observe.metric("substep.duration", 50, Map.of(
        "gen_ai.agent.name", "diagnosis-agent", "substep.name", "retrieve-alarms"));
    observe.metric("gen_ai.client.token.usage", 120, Map.of(
        "gen_ai.agent.name", "diagnosis-agent",
        "gen_ai.request.model", "model-1",
        "gen_ai.token.type", "input"));
    observe.log("gen_ai.agent.a2at.agent", LogSeverity.INFO, "agent completed", Map.of(
        "gen_ai.agent.name", "diagnosis-agent",
        "agent.skills", List.of("alarm-search"),
        "agent.state", "completed"), span);
    span.ok();
}
```

## 4. 跨进程 Trace Context 与异常

调用方使用 `TraceContextPropagation.inject` 写入当前 W3C `traceparent`；接收方使用 `extractToCurrent` 恢复上下文，再创建 Server Span。

```java
try (var client = observe.trace("SendMessage", SignalKind.CLIENT, attributes);
     var scope = client.makeCurrent()) {
    TraceContextPropagation.inject(headers, Map::put);
}

try (var scope = TraceContextPropagation.extractToCurrent(headers, headerGetter);
     var server = observe.trace("SendMessage", SignalKind.SERVER, attributes)) {
    try {
        handleRequest();
        server.ok();
    } catch (RuntimeException error) {
        server.error(error);
        throw error;
    }
}
```

`error(Throwable)` 会记录异常并将 Span 状态置为错误。只调用 `error()` 时仅更新状态。

## 5. 配置 Collector

仓库的 `examples/collector-config.yaml` 同时开放以下 OTLP receiver：

| 协议 | 地址 |
|---|---|
| gRPC | `0.0.0.0:4317` |
| HTTP/Protobuf | `0.0.0.0:4318` |

本机验证可使用：

```powershell
otelcol --config=examples/collector-config.yaml
```

该配置将 Trace、Metric、Log 输出到 Collector 的 debug exporter。部署环境请将对应 pipeline 的 exporter 替换为实际存储或转发端。TLS 与 Bearer Token receiver 示例见 `examples/collector-auth-tls-config.yaml`。SDK 支持 OTLP gRPC 和 HTTP/Protobuf，暂不开放 HTTP/JSON。

有关 SDK 侧的端点、认证请求头、受信 CA 和导出超时，请查看 [API 参考](API参考.md#sdkconfig-与-sdkconfigbuilder)。

## 6. 信号定义与校验

三份定义随 JAR 一同打包：

| 文件 | 覆盖范围 |
|---|---|
| `src/main/resources/observability/a2at.yaml` | A2A、四类 A2A-T 扩展 |
| `src/main/resources/observability/workflow.yaml` | Workflow、Step |
| `src/main/resources/observability/agent.yaml` | Agent、Substep、Token 用量 |

每个 YAML 均声明 `version`、属性类型及其 OpenTelemetry 名称、Trace/Log 可用属性和必填属性、Metric 类型与维度。调用 SDK 时会按以下顺序校验：

1. 根据信号名称查找对应 Trace、Metric 或 Log 定义；
2. 校验属性名称是否在该信号的允许列表中，校验必填属性与类型；
3. 对 A2A-T 的消息 Trace 和 Log，依据 `extension.name` 选择四类扩展的属性列表；
4. 对 Metric，校验该 Metric 的允许维度、必填维度与数值类型。

除 `extension.name` 外，SDK 不限制业务属性的枚举取值；属性的名称、类型、信号归属及必填性仍会校验。

### 修改定义

定义变更应在相应 YAML 完成，并递增该文件的 `version`。同时更新：

1. 覆盖新名称、属性和拒绝场景的单元测试；
2. 一个可运行示例；
3. 中英文 API 参考和开发指南中的信号表或示例；
4. `CHANGELOG.md` 的待发布说明。

当前 SDK 的 YAML 为内置资源；修改后需要构建并发布新版本，运行中的应用不会自动重新加载定义。

## 7. 兼容性与版本

- 版本使用语义化版本格式。修订号用于兼容性修复；新增兼容能力使用次版本号；破坏性公共 API 变更使用主版本号。
- `net.openan.observability` 中的公开类、方法、枚举值和 Builder 方法视为公共 API。内部包 `net.openan.observability.internal` 不属于兼容性承诺范围。
- 首个正式版本发布后，以其 Maven Central 构件作为二进制和源码兼容性基线。后续变更可通过以下命令检查：

```powershell
mvn -B -ntp -Papi-compatibility '-Dapi.baseline.version=0.1.0' verify
```

- 需要移除或替换公开 API 时，先在一个次版本中标记为 `@Deprecated`，说明替代方案，并至少保留至下一个主版本。
- YAML 定义的新增属性、信号或可选维度通常属于兼容变更；移除或收紧已有名称、类型、必填属性、允许属性和指标维度时，需要按破坏性变更处理。

## 8. 质量检查与发布演练

`mvn verify` 会执行依赖上界检查、基础源码卫生检查、单元测试，以及源码和 Javadoc 构件生成。源码卫生检查会拒绝 Tab、文件末尾缺少换行和冗余导入，不会对现有代码做批量格式化。

仓库提供一个手动触发的 **Release verification** 工作流。它会校验输入版本是否符合语义化版本、检查 Central 与 GPG 所需密钥、生成签名构件并验证签名。该工作流只执行 `verify`，不会创建 Tag、上传构件或发布版本。

本地没有签名密钥时，可执行以下发布前检查：

```powershell
mvn -B -ntp -Pexamples -Drevision=0.1.0-rc.1 clean verify
mvn -B -ntp -DskipTests -Drevision=0.1.0-rc.1 verify org.cyclonedx:cyclonedx-maven-plugin:2.9.1:makeAggregateBom
```

SBOM 输出为 `target/bom.json` 与 `target/bom.xml`。CI 还会使用独立 Maven 消费者向 Collector 发送数据，并检查 Collector 输出中是否同时出现预期的 Trace、Metric 与 Log 信号。

## 9. 测试和示例

在仓库根目录运行全部测试及示例编译：

```powershell
mvn -B -ntp -Pexamples clean verify
```

运行 Workflow / Agent 示例：

```powershell
$env:OTEL_EXPORTER_OTLP_PROTOCOL = 'grpc'
$env:OTEL_EXPORTER_OTLP_ENDPOINT = 'http://localhost:4317'
mvn -B -ntp -Pexamples test-compile exec:java '-Dexec.classpathScope=test' '-Dexec.mainClass=net.openan.observability.example.WorkflowAgentExample' '-Dexec.args=local' '-Dexec.cleanupDaemonThreads=false'
```

运行独立 Maven 消费者验证：

```powershell
mvn -B -ntp -DskipTests install
Push-Location consumer-smoke
mvn -B -ntp package exec:java '-Dexec.mainClass=net.openan.observability.consumer.ConsumerSmoke' '-Dexec.args=local' '-Dexec.cleanupDaemonThreads=false'
Pop-Location
```

更多 A2A、A2A-T 扩展和跨进程调用示例位于 `examples/src/main/java/net/openan/observability/example/`。
